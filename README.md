# ClimbAI Coach — Technical Blueprint

Scientifically-grounded, hyper-personalised climbing training plans generated by an LLM
under hard sports-science constraints. No fixed templates, no scraped platforms — a
deterministic prescription engine with a language model doing the part it is actually good at.

## The core architectural thesis

> **The LLM designs the block. It never does the arithmetic.**

The model chooses *which* protocols, on *which* days, in *what order*, at *what relative
intensity*, under this athlete's equipment, injuries and schedule — and explains itself.
A pure, unit-tested TypeScript engine converts relative intensities into kilograms, applies
injury clamps, and rounds to plates the athlete owns. A rules validator sits between them and
rejects anything that violates training-science invariants before a human ever sees it.

```
 SQL → context (≤2.5k tok) ─▶ cached doctrine prompt ─▶ LLM ─▶ schema ─▶ validator ─▶ load
                                                                  ▲           │       resolver
                                                                  └─ repair ◀─┘         │
                                                                    (×2, then           ▼
                                                                  deterministic    immutable
                                                                     fallback)     plan version
```

## Science encoded

- **Clustered stimuli** — one primary stimulus per session; max finger strength and anaerobic
  capacity may never share a session; mandatory within-session ordering; 48/72 h recovery gaps;
  weekly hard-day caps scaled to training age.
- **Protocols with exact parameters** — Eva López MaxHangs (MAW and MED), Lattice 7:3 repeaters,
  4×4 power endurance, limit bouldering, campus (gated), ARC, weighted pull-ups.
- **Progressive overload** — normalised load index (total load ÷ bodyweight on 20 mm), Epley 1RM,
  4-week 3:1 mesocycles, one progression dimension per protocol per week, RPE-driven
  autoregulation, acute:chronic workload monitoring.

## Safety posture

Injury contraindications and pain flags are enforced in code, not by prompt instruction alone:
every rule stated in the prompt is independently re-checked by the validator, because a prompt
rule you do not also validate is a suggestion. Tier-3 (pain/injury) responses are never
delegated to the model. The app does not diagnose, rehabilitate, or advise on body composition.
